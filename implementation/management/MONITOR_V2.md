# 每小时训练监督的更新记录覆盖

原管理监控器只读原生日志末尾 128 KiB，并从该尾部查找 optimizer 指标。针对每小时监督，较早提交的更新记录可能已经位于这个窗口之前。CPU 回归保留原逻辑，复现了指标被后续进度行覆盖后的漏读。

`monitor_training_current_v2.py` 继续使用紧凑尾部读取当前进度，同时从原日志起点扫描 optimizer 指标。扫描绑定开始时的文件字节边界，有30秒预算，输出最后三条原始匹配行以及扫描字节数、边界和完整性标记。日志被截断或预算耗尽时，完整性为 false，更新情况保留未知。外层 SSH 仍有45秒上限，传输错误保留上一份完整观测。

匹配行数只表示发现了多少条原始日志，不直接表示验收后的更新次数。真实参数更新仍需 first-update-v4 的原生指标、参数变化及同步证明，后续由逐相邻版本检查器验收。完整扫描且没有更新记录时，才可以结合当前阶段报告尚无原生更新证据。

Mac和Node各12项CPU检查通过，分别为8项扫描回归和4项原子观测捕获回归。覆盖旧窗口漏读、最后三条输出、同一行双字段、空文件、预算耗尽、并发追加的固定边界、截断、无效UTF-8及原有传输异常留证。检查期间没有模型、Judge或GPU调用。

实际接线使用当前同一训练owner。科学训练源码、参数、预算、数据及进程继续沿用原版本。原监控器和本机 `capture_training_observation_v1.py` 保留，当前本机捕获入口只替换为v2监控器。
