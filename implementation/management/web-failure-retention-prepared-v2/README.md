# 检索失败留档准备

当前broker运行在Mac，通过SSH反向隧道向H20网关的127.0.0.1:19180提供检索。当前网关对broker非成功响应调用raise_for_status，模型侧因此收到HTTP500。2026-11-17 10:49日志冻结前缀15489540字节，正确路径有6850次200及585次500。这是当前gateway日志前缀的累计请求数，不能当成单批或单题。584条HTTPStatusError、1条连接异常及1条读取超时是异常日志记录数，异常链与请求不能直接逐项一一对应。

broker只保存成功网页。原失败只返回异常名称及文本，未保存相应错误正文，Mac broker日志当前为空。服务器异常栈保留了502转500链路。已检查的5次原正确CLI失败没有精确请求关联标识，无法仅凭并发日志时间将各次错误归因到某个网站、HTTP状态或网络故障。旧数据保持缺失，原请求不重放。

准备版仅在原失败处理内保存已读取请求字节及完整性标志、原broker错误响应、异常栈、时间和上游HTTP状态。状态码、响应内容、成功检索逻辑、工具接口及重试策略均保持原行为。磁盘写入失败记录stderr后继续发送原错误响应。此改动不修复检索本身。上游HTTP错误原网页正文仍不读取，避免引入额外阻塞。

原版与准备版使用9个CPU HTTP fixture对比，覆盖403、DNS、超时、JSON错误、Unicode、空请求、留档磁盘失败、超限请求和成功路径。fixture全部为本机回环，外部网页/模型/Judge调用0。测试未穷尽磁盘挂起或断电情形。

当前服务源码与进程未更换。后续受控无在途边界才可部署，实际故障捕获尚待验收。准备版副本用于归档和测试，不能当作已生效。
