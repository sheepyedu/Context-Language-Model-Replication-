# Summary 条件准备

本目录实现 Summary 的上下文替换组件。当前 C2 使用原 CLM harness。S0/S1 的完整执行器、评价器和训练入口仍在实施，本文所列 CPU 验收覆盖该组件。

## 来源与范围

论文附录 E 指定 RL 对照在 28672 Token 时压缩，最多 100 个任务回合。论文其他通用实验的 75% 触发条件单独记录。压缩提示使用固定公开 Codex 源码树 `5cb38e79842a0e0a6dca5bb97874163e8ee50129` 的两份文件，原文、SHA 和许可证保存在 `prompts/`。作者实际使用的历史提示版本未提供，此固定版本为复现默认值。

## 当前组件

- 系统消息和原任务消息完整保留。累积历史被一条带 Codex 前缀的摘要替换。
- 达到触发值后，完整历史和压缩提示进入一次普通模型请求。请求关闭工具，摘要文本由模型生成。
- 上下文上限 32768，单次输出上限 4096。输入长度决定实际剩余输出空间，这一预算边界处理属于复现默认值。
- 模型请求通过调用者的普通 rollout transport 留档。组件额外保存每阶段的 INTENT、原始响应及接受或拒绝记录。
- 稳定 task-stage ID 和独占目录标识一次压缩。未知结果保留原输入和错误，原阶段已经消费的请求得到保护。
- 空摘要、工具调用、length 终态和压缩后仍超限按有界负结果留档。完整轨迹与费用继续保留。
- S1 的摘要生成 Token 需要接受 task-only 信用，效率权重为 0。该项是后续训练接线的契约。

## 验收

`check_summary_context.py` 覆盖 14 个 CPU 场景，包括保护前缀、完整输入、预算边界、已完成截断、未知请求、跨恢复阶段去重。

`check_summary_tokenizer.py` 使用实际 Qwen3.5-9B tokenizer 和官方 Bash schema，在真实模板下构造 28672 Token 边界并完成替换，压缩请求输出空间满足服务上限。模型返回采用固定 CPU 样例，新增模型调用为 0。

首次实际 tokenizer 检查发现 Transformers 5.3 默认返回 BatchEncoding，直接取长度会得到字段数 2。显式设置 `return_dict=False` 并验证整数 Token ID 列表后通过。原失败日志保留，生产 C2 从未使用该准备组件。

## 后续接线

完整 Summary 执行器需要复用普通 Bash 执行与输出记录，逐请求记录实际输入和输出。S0 使用原始冻结权重进行评测，S1 使用相同初始权重和二值任务奖励训练。所有普通生成及摘要生成费用进入同一唯一调用账本。完整接线和真实任务验收完成后才能启动 S0/S1。
